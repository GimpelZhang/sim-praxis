# Task 5 三态判据（首呼前冻结；与 `verdict.py` 逐位同义）

本文件是 Task 5「agentic 前提」实证的唯一判据文本。付费墙开跑后不得改字；
`tests/milestone25/test_task5_wall_contracts.py` 用合成 trace 对本文件每条
规则做必绿/必红变异反证。任何引擎脚手架改动（放宽阈值、改子帽、改白名单）
都只能发生在首呼之前；首呼后发现歧义，按「疑罪从有」处理，不改判据。

## 1. 共享池与子帽（区间件 `interval_t5.json` 钉死）

- 共享池总量 **28** ＝ 基础池 25 ＋ 储备 3；
- 墙 A 历史规模 sA=60（Phase 2 Task7 LIBERO 战役 coding 实呼），
  墙 B 工程规模 sB=30（run_5 机判战役 B-eng 30 呼，seq398–436；
  另 9 呼 B-cap 不进分母，见 `SEQ_SPLIT.json`）；
- 子帽公式（只在首呼前可整体冻结，跑后不可调）：

  `子帽_x = clamp( half_up(25 · s_x / (sA + sB)), 9, 16 )`

- `half_up` 为四舍五入到整数的**半值向上**法（Decimal ROUND_HALF_UP；
  整数恒等式 `(2·num + den) // (2·den)` 双实现互证），**禁止** Python
  内建 `round` 的银行家舍入（半数偶）；
- 代入 (60,30)：A = half_up(16.667) = **16**，B = half_up(8.333) = **9**，
  和 25，储备 3；clamp 未触发，`double_half_tie=false`；
- 极端边界（变异反证用）：sB→0 时 A 仍封顶 16、B 仍保底 9（和 ≤25，
  缺口不补），如 (1000,1)→(16,9)、(1,1000)→(9,16)。

### 1.1 双半值平局（double-half tie）

当两侧原始份额小数部分都恰为 0.5（如 sA=sB=30 时 12.5/12.5），公式
无法同时 half-up（和会变 26）。冻结规则：**先跑的墙半值向下（floor），
后跑的墙半值向上（ceil），和强制 =25**。默认跑序 A 先 B 后：
(30,30) A 先 → A=12、B=13；若跑序被迫 B 先（未来重排）→ A=13、B=12。
本任务实参 (60,30) 不触发平局，记录规则只为判据完备与测试反证。

## 2. 预算纪律（跑后不可变）

- 两墙子帽独立：墙 A=16、墙 B=9；**禁止跨墙借调**（A 的余额 B 不能用，
  反之亦然）；
- 储备 3 的**唯一**用途：供应商污染取证后的重跑（见 §4）；正常修复、
  换思路、重试一律先用本墙未花余额；
- 每次实呼（成功、失败、发网前失败）都占本墙 seq 并进 ledger；
  preflight_blocked 不占实呼；
- 任一墙「到子帽仍未过墙」即熔断判「未过墙」：不得抬帽、不得改种子、
  不得改闸定义/合同、不得换模型（换模型按硬规则 1 另行 STOP 请示）。

## 3. 工程闸通过与 50% 效率线

- 墙 A 工程闸：`wall_a_runner.py` 全 12 项检查 PASS、rc=0；
- 墙 B 工程闸（B-eng）：`wall_b_checker.py` 全部检查 PASS、rc=0；
- `calls_to_rc0`：从本墙首个付费 seq 到**评分器首次 rc=0 的那次代码版本**
  为止，本墙实呼总数（失败/空响应/供应商错误都计入）；
- 效率线（AC-T5-4）：calls_to_rc0 ≤ s_x 的 50%（整除下界）：
  墙 A **≤30**（注：sA=60；同时受硬子帽 16 约束，故实际 ≤16 即天然在线内，
  50% 线对 A 的作用是与历史规模对账）、墙 B **≤15**（受子帽 9 约束同理）；
  判据函数以历史 s_x 为分母计算阈值，子帽是更紧的运行时硬帽；
- 「零引擎脚手架升级」：不允许 lead/引擎侧人工递提示、放宽合同、改评分器、
  给答案片段；trace 中出现人工介入即该墙判负；
- 「零人工介入」：不允许任何人在环操作（Gate 按钮、人工改文件、人工跑
  评分命令）。看门狗/熔断是引擎自动行为，不算人工。

## 4. 供应商污染与储备重跑

- 触发条件：有证据表明模型侧失败来自供应商/网关（非代码问题）——
  连续供应商错误、空响应、与请求无关的回显等，且经 ledger seq 推进、
  响应原文、时间戳三证固定；
- 重跑机会**每墙至多一次**，先用本墙未花余额，余额不足才可申请储备；
- 单墙重跑实呼 **≤4**；储备先到先得、跨墙不得借用，全局总额 ≤28；
- 重跑后仍无法判定工程能力（污染与代码失败不可分）→ **疑罪从有**：
  该墙按「未过墙」记，不判「不确定」、不抬帽三审。

## 5. 三态判决表（纯函数，输入两墙的 WallResult）

判决按下列顺序短路求值（`engineering_verdict`）：

1. 任一墙处于「待重跑」（已确认污染、重跑未完成）→ **不确定**；
2. 任一墙「污染且不可判定」（疑罪从有）、靠脚手架升级通过、靠人工介入
   通过、到子帽未过、calls_to_rc0 超 50% 线 → **不成立**（reason 逐项记录）；
3. 两墙工程闸都干净通过（无升级/无人工/未触帽/在 50% 线内）→ **成立**；
4. 其余「一墙干净过、一墙干净失败（未触帽、未升级、未污染）」→ **不确定**。

三态标签逐字：`成立` / `不成立` / `不确定`。

## 6. B-cap 独立轴（不触发 D-4）

墙 B 历史战役含 39 呼 = B-eng 30 + B-cap 9。评分器只判工程仪器合格
（B-eng）；B-cap（可选 `design_pour_trajectory()` 的 speed≤0.20、
clearance≥0.012）只描述性记录：

- B-eng 过 + B-cap 也过：仪器合格且能力墙未在工具层复现；
- B-eng 过 + B-cap 不过：**「G.8 能力墙在工具层复现」独立结论**，照发，
  不触发 D-4 STOP；
- 只有 B-eng 不过才进入 §5 的三态（并按 D-4 报用户）。
